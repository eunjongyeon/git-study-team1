## checklist

팀 저장소 1개, 팀원 4명 모두 Collaborator로 등록됨 o

team-chat.txt 에 팀원 4명 메시지가 최소 2바퀴 이상 이어져 있음

팀원별 브랜치 4개 생성 → review.md  작성 → main으로 merge 완료

merge 중 충돌 상황 1회 이상 발생 및 해결 기록 있음

stash → restore 과정 1회 이상 실습 및 기록

삽질 기록 팀원당 1개 이상 (총 4개 이상)

커밋 메시지 컨벤션 연습 및 예시 정리

README.md에 위 1~6번 항목 모두 포함



1번 부질문
팀원 각자 저장이랑 커밋이 뭐가 다른지, 본인 나름대로 이해한 대로 2~3줄씩 써주세요. 
교과서적으로 작성하지 않으셔도 됩니다.
은종연
- 저장은 수정한 내용을 부분마다 개인적으로 저장하는 것이고, 커밋은 그렇게 수정이 완료된 파일을 Push해서 협업을 위해 공유하거나 서버로 올리기 위해 사용하는 기능이다.


2번 부질문
은종연
언제/왜 Pull을 먼저 했는지, 안 하면 어떻게 되는지 겪어봤다면 그 얘기도
- 다른 팀원이 push 했을 때, 겪어보진 않았는데 push가 리젝되는 걸로 알고 있음
Commit 메시지 뭐라고 썼는지, Push 눌렀을 때 결과가 어땠는지
- 파일 만들었으면 제작, 내가 한 거 간단하게 작성 타인이 이해할 수 있도록
본인 차례를 기다리는 동안 다른 사람 화면에서(혹은 GitHub Desktop History 탭에서) 뭐가 보였는지
- 다른 사람이 commit한 내용, 제목, 그리고  No newline at end of file이라는 문구


조명주
- 저장은 이때까지 한 기록을 모두 한꺼번에 기록한 것이지만, 커밋은 내가 수정한 부분을 기록한 것이다.(저장보다는 조금 더 세부적인 부품을 기록한다는 느낌으로 이해했습니다.)

조명주
- 순서대로 팀원이 작성을 완료하면 pull 했음
- 커밋 메세지에는 어떤 내용을 적었는지 요약해서 적음. push를 하니, 커밋 부분이 사라짐
- 하나씩 히스토리가 추가되었음
